    Architecture

    Un moteur qui prend un audio ou une vidéo quelconque (récitation, prière, cours mêlant français, arabe, hadiths) et produit une timeline horodatée des versets du Coran récités, puis restitue leur texte exact et leur traduction officielle.

    1. Invariants#

    Ces règles ne se négocient pas : chaque changement les respecte, et chaque brique est testée contre elles.

    #InvariantConséquence technique
    I1Le texte arabe affiché ne vient jamais d’un modèle. Il vient du corpus, par consultation VerseRef → texte.L’ASR ne sert qu’à localiser. Aucun LLM génératif dans la chaîne.
    I2Traductions officielles, non modifiées, versionnées.Source QuranEnc ; translation_id + version stockés ; attribution affichée.
    I3Nommer un faux verset est pire que n’en nommer aucun.Sous le seuil : UNCERTAIN ou rien. La précision prime sur le rappel.
    I4Tout ce qui n’est pas du Coran est étiqueté et ignoré.Classe NON_QURAN, jamais un verset « le plus proche ».
    I5Chaque verset porte un statut de preuve.RECOGNIZED (entendu et aligné), INFERRED (déduit d’un trou), UNCERTAIN.
    Pourquoi I3 ?

    Un faux verset nommé avec assurance trompe l’écouteur ; un silence honnête le laisse écouter lui-même. C’est pour cela que la barre d’état des intervalles distingue toujours reconnu, déduit et incertain.

    2. Vue d’ensemble : le pipeline#

    Neuf briques s’enchaînent, de l’extraction audio au rendu. Les trois du milieu décident de ce qui est du Coran.

     fichier audio/vidéo
        │
 [B1] AudioExtractor ──────── ffmpeg → WAV mono 16 kHz
        │
 [B2] SpeechSegmenter ─────── découpe en segments de parole (pauses / waqf)
        │
 [B3] LanguageGate ────────── français / autre langue → NON_QURAN direct
        │  (arabe seulement)
 [B4] QuranASR ────────────── transcription orientée Coran + timestamps mots
        │
 [B5] QuranicityGate ──────── est-ce VRAIMENT du Coran ?
        │
 [B6] VerseMatcher ────────── texte normalisé → candidats (VerseRef, mots, score)
        │
 [B7] SequenceDecoder ─────── Viterbi : continuité, sauts, répétitions, trous
        │
 [B8] Timeline ────────────── [ {ref, mots i..j, t_debut, t_fin, statut}, NON_QURAN… ]
        │
 [B9] Renderer ────────────── texte Mushaf (I1) + traduction (I2) · JSON, SRT/VTT

    3. Les briques : contrats#

    Toutes les interfaces vivent dans src/aqr/domain/ports.py, les implémentations dans src/aqr/adapters/. Chaque port a un test de contrat que toute implémentation doit passer.

    BriquePortEntrée → sortieImplémentation V1
    B1AudioExtractorchemin fichier → AudioClipffmpeg
    B4QuranASRsegment → Transcript (mots + temps)FastConformer-Quran, challengers Whisper et Muno
    B5QuranicityGateTranscript → score ∈ [0, 1]double ASR + couverture d’alignement
    B7SequenceDecodercandidats → TimelineViterbi / HMM

    Exemple : le port B4#

    src/aqr/domain/ports.pyPython
    # --- B4 --------------------------------------------------
class QuranASR(Protocol):
    riwaya: Riwaya

    def transcribe(self, clip: AudioClip, span: TimeSpan) -> Transcript: ...

    Un nouveau modèle se branche en écrivant un adaptateur qui respecte ce contrat, sans toucher au domaine. Les détails sont dans les décisions ADR et dans l’évaluation.

    4. Les pièges connus#

    Piège n°1 : l’ASR du Coran « voit du Coran partout »#

    Un modèle affiné sur le Coran projette n’importe quel arabe (hadith, dou’a, khutba) vers le texte coranique le plus proche. Un segment n’est accepté que si plusieurs signaux concordent :

    1. un ASR généraliste transcrit le même segment ; une forte divergence signifie « pas du Coran » ;
    2. la couverture d’alignement atteint au moins N mots consécutifs avec une similarité au-dessus du seuil ;
    3. en option, des indices acoustiques de tartil (débit, allongements).

    Piège n°3 : versets identiques#

    Le verset فَبِأَيِّ آلَاءِ رَبِّكُمَا تُكَذِّبَانِ revient 31 fois dans Ar-Rahman. Le contexte (verset précédent et suivant) lève l’ambiguïté, d’où un décodage de séquence plutôt qu’un verset à la fois. Si l’ambiguïté persiste : UNCERTAIN, avec la liste des candidats.

    5. Modèle de données#

    VerseRef(surah: 1..114, ayah: 1..n)            # validé contre le corpus
WordSpan(ref: VerseRef, first_word, last_word)  # plage de mots dans un verset
TimeSpan(start_s, end_s)                        # secondes, start < end
Detection(span, time, status, confidence, candidates)
